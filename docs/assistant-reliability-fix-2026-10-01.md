# AI 助手可靠性修復與逐題驗證 — 2026-10-01

## 修復與界線

- 正常路徑維持同一模型回應做語意範圍判斷，沒有關鍵字分類、沒有新增獨立 classifier。完整 JSON 決策亦經相同 schema、來源、權限及寫入確認檢查。
- 格式失敗只修復一次，改用 JSON 輸出，不再重複強制同一工具格式；任意自由文字、含有 JSON 片段的文字、無權限答案與未驗證工具均不可直接展示或執行。
- 暫時連線／HTTP 429／5xx 最多重試一次，尊重短 Retry-After，長 Retry-After 不重試。重試共用同一額度准入、最多三次模型呼叫及 40,000 tokens 預留；失敗未知用量仍保守記帳。
- 總處理上限由 25 秒改為 30 秒，單次模型上限仍 25 秒，保留 40 秒租約；一般成功路徑不增加模型呼叫。不是無限延長等待或無限重試。
- 超時、決策格式、供應商繁忙、連線失敗、設定錯誤、單次預算及未知內部錯誤分開提示；JSON／SSE 保留查詢編號及對話 ID。SSE 有保活和修復進度。私有執行紀錄保留每次耗時、stop reason 及格式檢查錯誤，不把原始模型思考或供應商私有錯誤交給用家。
- 若 transport failure 的保守預留使重試預算不足，提示原本的連線／超時原因，不把短問題誤稱太複雜。沒有額外呼叫模型。
- 模型選 insufficient_data 時，統一說明「相關但資料不足」，不可一面標示相關、一面文字拒絕為離題，亦不可塞入無來源維修操作。車主基本欄位用途明確屬服務範圍。
- 普通帳戶每日五次、管理員豁免、全站成本上限、登入及寫入確認均保留。未新增正式資料庫 migration，未測試寫入正式車輛資料。

- 另外直接呼叫真實供應商的 JSON-only 決策：一次未取得有效 scope 決策；再次同題取得完整 JSON reject。這不是零失敗保證。真正 API 重測已有 JSON 修復及讀取續接成功證據；仍可能遇到供應商不遵守格式、網絡故障或超時。

- 完整三十題之後僅補上「transport retry 預算不足時保留原始原因」的錯誤分支、OpenAI 壞 JSON 進相同格式修復及只在私有紀錄保留診斷；已另作單元／資料庫及瀏覽器故障驗證，正常模型決策路徑未改。

HTTP 200 · answer · 12.82 秒 · 1 次模型呼叫

> 新車或剛買的車北上維修前，最重要是分清「維修」與「保養／保固索賠」，並把資料先講清楚，避免到場後被當成一般維修收費。
